# 部品の形と余白、影を確認する

対象: 組み込み38形状、およびシーケンスの参加者・ライフライン・活性区間・メッセージ・フレーム。
確認ページ: `component-study.html`。

## 確認条件

- 現在のBusiness配色・余白設定と、二層のbusiness-shadowを使用。
- 同じ部品を影なし／ありで表示。100%倍率、図全体の最小キャンバス余白のみトリミング。
- 基本形状は短文「注文を確認」と長文「法人顧客の注文内容と配送先を確認して出荷を手配」。折り返し幅180px。ただし調整後の円・菱形は既定の120pxを使用。
- ER・クラス・グループ・シーケンスは実際のDSLで内容入りの例を使用。
- スライド部品にも180pxの折り返しを指定。広い部品で右側が余るのは、この試験条件の影響を含む。通常のスライド幅での欠陥とは判定しない。
- 大見出し・区画見出し・数値のウェイトを一律550で上書きしない。基本形状の14pxラベルにのみBusinessの550を適用。
- 全39確認項目の短文・長文をブラウザーで描画。代表例の視覚確認と実装の寸法計算を照合。任意のラベル長・全画面サイズを網羅する保証ではない。

## 初回確認時の優先順位（修正前）

1. **不具合修正: `uml-object` の複数行下線。** 下線が `node.height / 2 + 11` に固定され、2行目を横切る。文字行に合わせた下線に変更する。輪郭や影の好みの問題ではない。
2. **見た目の調整: database。** 上蓋13px、文字位置は中心＋5px、高さは文字高さ＋42pxで、通常ノードの上下余白と別管理。上蓋下端から本文までの見かけの余白を基準に組み直す。
3. **見た目の調整: circle / diamond / usecase。** 長い本文を入れると面積が増える。安全な内接領域を守りながら折り返し幅を形状別に検討する。長方形と外寸を一律に揃えない。
4. **人物・構造線のトーン整理。** actorはノード枠と同じ淡色のため、本文に比べて人物が弱い。人物など形状の意味を担う線には、通常ノード枠より濃い役割色が適する。
5. **影の適用範囲を仕様化。** 現在は元の形状にfilterがある面だけが対象。`business-shadow`でもすべての部品に影が付くわけではない。状態記号・文字・グループの影なしは自然。スライドのカード系と注記系の違いは意図として明文化する。

## 前回に変更した内容

共通の形状レンダラーを修正したため、Business以外のテーマにも適用される。

- `uml-object`: 固定位置の線を廃止し、SVGの文字装飾で各行に下線を付けた。複数行で本文を横切らない。
- `database`: 蓋の高さを13pxから10pxに変更。本文を蓋下端と底面の間に配置し、テーマの上下余白を反映。輪郭の上下端も楕円弧に揃えた。
- `circle` / `diamond`: 既定の折り返し幅を120pxに変更。明示した`wrapWidth`は維持する。確認ページではこの2形状の180px固定指定を外した。
- 長文例の描画外接は円211×211pxから169×169px、菱形368×104pxから256×144px。菱形は高さを増やして横広がりを抑える調整。
- ブラウザーで上記4形状の長文・影あり／なしを目視確認。型チェック、全134テスト、ビルド成功。下線、蓋下の余白、円・菱形の文字保持と輪郭内への収まりを回帰テストで確認。

人物の線、スライド部品、`uml-required-interface`の大きさは、次の追加確認で見直した。

## 人物の線と部品の余白を直した結果

2026年9月6日に、現在のコードとテストを読み、Microsoft Edgeで表示を確かめた。

- 人物の線は、枠の色である`nodeStroke`から、線の色である`edgeColor`へ変更した。Businessでは`#c8d2e0`から`#7a8aa3`となり、人物を見分けやすくなった。線の太さと人物の大きさは同じ。default、midnight、独自の配色でも、そのテーマの色を使う。
- `uml-required-interface`は、半円の上端が部品の原点より14px上に出ていた。半円を18px下へ移し、上端を原点から4px下に収めた。半円の幅36px、高さ18pxは同じ。Businessの短い文では、計算上の大きさは85×57pxのまま、描かれた範囲は65×56pxから65×38pxになった。文字を大きくした場合は、半円と文字が重ならないように文字の位置と部品の高さを増やす。
- `slide-milestone`は、期間の文字領域がカードの上端に接していた。期間と、その下の見出しと本文を7px下げた。期間の上に7pxの余白ができた。期間と本文があり、高さを小さく指定した場合は、折り返し分を足す前の高さを118px以上にする。期間がない場合の文字位置は同じ。
- `slide-quote`は、引用符の文字領域が原点より3px上に出ていた。引用符を7px下げ、上に4pxの余白を確保した。
- `slide-card`など、ほかのスライド部品は文字が枠に収まっていた。カードの左の色線や、引用の広い余白は今後の見た目の検討として残す。

## 固定した枠が重なる場合の結果

営業部の部品を`x=100, y=100`、業務部の部品を`x=180, y=150`に固定した例を確認した。二つの枠は重なるが、部品は固定した位置に残り、枠より前に描かれる。更新、自動配置、テーマの切り替え、配置の保存と読み込みでも位置を保つ。

この例では、営業部の部品が業務部の見出しを隠していた。修正後は、枠の上部に空きがあれば見出しを横へずらす。空きがない場合も、見出しを部品と線より前に描き、文字に背景色の縁を付ける。部品の固定位置は保つ。二つの部品の固定を外して自動配置すると、枠の重なりは解消する。

再現する図は次のとおり。上記の座標を、`overlay.nodes.a`と`overlay.nodes.b`に`manual: true, pinned: true`とともに指定する。

```text
@graph
group sales "営業部" {
 a "注文を確認"
}
group ops "業務部" {
 b "出荷を手配"
}
```

## テストと表示で確かめた範囲

- `npm test`で全149テストが成功。自動配置、手動配置、テーマ、編集、出力の既存テストを含む。`npm run typecheck`と`npm run build`も成功。
- 人物の色、半円と文字の収まり、スライドの余白、二つの固定位置の保持をテストに追加した。半円は`theme.fontSize`を13、14、20、24にして確認した。
- `component-study.html`の39項目を、短い文と長い文、影ありと影なしで表示した。合計156件で、SVGの`getBBox()`による部品の範囲からのはみ出しは0件。影と線の太さはこの計測に含めない。半円の線の太さを含めた収まりは別のテストで確認した。
- スライド10種類は、180pxの折り返し指定を外した長い文でも範囲内に収まった。人物、半円、期間を示すカード、引用、固定した枠の重なりは画像でも確認した。ブラウザーでの実行エラーは0件。
- 任意のフォント、文字サイズ、文の長さ、固定位置の組み合わせをすべて確かめたわけではない。カードや引用の装飾の見直しは残る。

- 上記の図と固定位置で、修正前に業務部の見出しが隠れることをブラウザーで再現した。修正後は標準テーマと`midnight`の両方で、見出しと部品の文字を読めることを画像で確認した。二つの部品の座標は変わらない。

- 空きがない場合は見出しを前に描くため、部品の文字と重なることがある。固定したすべての部品と見出しの間に、必ず空きを作る処理ではない。
