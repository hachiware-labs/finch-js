# 配置・ルーティング評価 — 第1回

2026-09-12。架空の10モデルを現在のローカル実装で生成し、Edgeの実ブラウザー描画をCodexが目視評価した。これは評価基準をすり合わせるための暫定採点であり、利用者による追跡時間の実験結果ではない。ライブラリ本体の修正や、採点後のレイアウト調整は行っていない。

## 採点基準 v0.1

4項目を各5点、計20点。同じ観察条件で比較し、各減点を表に記した。

| 項目 | 観察すること |
| --- | --- |
| 配置 | 読む方向、主経路、階層、同段の整列、関連の近さ |
| 経路 | 接続元・接続先を追えるか、交差の曖昧さ、共有線、迂回、折れ曲がり |
| ラベル | 文字の欠け・重なり、線や多重度との対応、分岐条件の位置 |
| 空間 | 可読性に必要な間隔、不要な余白、極端な縦横比、混雑の偏り |

5=今回の例で支障を認めない、4=軽微な改善余地、3=追い直しが必要、2=繰り返し迷う／一部判読困難、1=主目的を大きく阻害、0=描画不能または必要情報が欠落。点差は厳密な測定単位ではない。合計とは別に、接続追跡を大きく阻害するものを「要改善」とする。

交差を一律に減点しない。forkの意味に沿う共有線は許容し、接続先を誤認しやすい密集・共有を重く扱う。長さも単独では減点せず、追跡負担や空間の偏りと合わせて判断する。同じ箇所を複数項目で減点した場合は、配置・追跡・空間それぞれの影響を明記した。

## 観察条件

- 同じ既定テーマ・既定ルーティング。手動座標、overlay、ピン留めなし。06のみソースの意味的な階層指定としてlayout=row/columnを使用。全例が完全なヒントなし配置ではない。
- 各図を固有寸法の100%で表示し、広い図は横スクロール。ページの外枠・最低幅600px・24pxパディングは空間採点から除外し、SVG自身の余白を見る。
- 全10例の構文検証とブラウザー描画に成功し、ページエラー0件。PNGを10例すべて目視確認。図の自動交差数計測や全ラベルの衝突検査を行ったという意味ではない。
- 低密度の図で高得点でも、高密度への耐性は保証しない。図種の優劣や合格率に集約せず、同一ケースの改善前後で比較する。
- HTMLは同梱のfinch.snapshot.jsを使う。初回PNG/SVG、DSL、採点JSON、寸法・geometryを保存。ビルドSHA-256: 4e1ba5da188a6d0257ec1cb171347fe2b7b1673288f61414a5b067b5816e0e03。作業ツリーには既存の変更があるため、コミット番号だけでは再現できない。

## 基準を確認したい論点

1. 05を10/20の「要改善」とする判断：交差の数よりも、接続追跡とラベルの対応を重く見ることでよいか。
2. 03・10の交差はジャンプで識別できるが、経路を3/5とする厳しさでよいか。
3. 02の長い正常経路は主軸維持の利点もある。空間3/5を厳しすぎると考えるか。
4. 配置と空間の同時減点は影響が重なるため、次回は配点の統合や重み付けを検討するか。

次回の候補は05の通路幅、06のデータ層の並び、03の戻り線の側をそれぞれ一つずつ変え、同じDSLの基準版と比較すること。今回の得点は固定し、基準変更時にはv0.2として10例すべてを再採点する。
