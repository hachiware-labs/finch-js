# 余白の使い方を配置手法にする — v0.1

2026-09-12。初回図05・06・10と利用者による修正版を比較して得た作業仮説。3例の目視観察に基づくため、普遍的な最適化規則や効果の実測値ではない。今回の文書化で配置エンジンや初回採点は変更しない。

## 基本原則

余白は、読者が「どこからどこへ、どの条件でつながるか」を識別するための領域として配分する。面積・線長・交差数の最小化は、意味と追跡性が同程度の候補同士で比較する。

余白を使う主体はノードだけではない。線、矢印、分岐条件、関係名、境界見出しにも場所が必要になる。ノードを配置して残った隙間に線と文字を押し込むと、外側が空いていても中央は混雑する。

## 余白の用途

| 用途 | 確保する場所 | 不足を見つける手掛かり |
| --- | --- | --- |
| 主経路 | 順に読むノード間の連続した軸 | 例外線が主軸に割り込み、順方向を追い直す |
| 接続通路 | 多数の線が通るノード間・層間 | 独立した線の重なり、矢印の密集、短区間での連続した交差 |
| 戻り通路 | 例外ノードから戻り先までの側方 | 下降線と上昇線の交差、狭い折り返し |
| 文字領域 | 分岐元の近く、対応する線の識別可能な区間 | 文字同士の近接、どの線のラベルか判断できない |
| 境界の区切り | 枠見出しの周囲、層の間、枠を横切る箇所 | 線と見出しの接触、枠線を接続線と誤認する |

同じ空間が複数の役割を担ってもよい。ただし、複数の独立した線を同じ位置に重ねて省スペース化する場合は、各接続を識別できることを確認する。forkのように意味に沿った共有線は許容する。

## 配置・ルーティングの手順

1. **変えてはいけない構造を決める。** 主な読む方向、正常経路、包含関係、並列区間、明示された順序を記録する。戻り線や依存線まで一律に下向きにしない。
2. **混雑する場所を先に見つける。** ノードの接続本数だけでなく、同じ隙間を通る独立した線、矢印、ラベルの数と寸法を見る。異なる位置に分散する接続は別々に扱う。
3. **通路と文字の場所を仮予約する。** 主軸、境界越え、例外の戻り道を置く。ラベルの実寸、矢印やジャンプの張り出し、線の識別に必要な間隔を含める。
4. **混雑を起こすノードの位置を比較する。** まず隣接順序、戻り先への近接、小さな段差を試す。それでも混雑する場合は局所の行間・列間、次いで配置方向やコンテナ内の向きを比較する。ノードを動かすたびに経路とラベルも再配置する。
5. **不足箇所だけを広げる。** 図全体の一律拡大は避け、問題の通路に空間を割り当てる。拡張が兄弟ノード・祖先枠・別の通路を圧迫しないか確認する。
6. **最後に縮めてみる。** 混雑解消後、余白を部分的に減らす。意味、線の識別、文字対応が悪化したら戻す。縮めても支障のない領域だけを圧縮候補とする。

終了条件は「これ以上小さくならない」ではなく、「重要な接続を迷わず追え、残った余白の役割を説明できる」。対称性や全ノードの整列は、この条件を壊さない範囲で整える。

## 通路幅の仮見積もり

同じ区間を並走する線について、横断方向に必要な幅を次のように概算する。

`必要幅 ≈ 両側の離隔 + (同時に並走する独立線数 − 1) × 識別間隔 + その区間で必要な追加の文字・矢印領域`

線数は図全体の本数ではなく、区間ごとの最大同時数。文字・矢印は実際の配置候補の外接領域から追加分を求める。経路方向を変えれば文字の横断方向の占有幅も変わる。これは候補生成の目安であり、固定のpx値やそのまま使える最適化式ではない。斜線、曲線、異なる高さのラベルには個別の衝突確認が必要。

## 評価基準の改訂案

空間の項目名を「空間効率」から「余白の配分」にする。5点を基準とし、面積そのものや長い直線だけでは減点しない。

| 点 | 判断基準 |
| --- | --- |
| 5 | 通路・文字・主経路・境界に必要な余白が配分され、観察した接続を迷わず追える |
| 4 | 一部に配分の偏りがあるが、実用上の追跡負担は小さい |
| 3 | 狭い箇所で追い直しが必要で、局所的な余白の再配分が有効と考えられる |
| 2 | 複数箇所で線・文字の識別が難しく、主要な関係も追いにくい |
| 1 | 配分の問題で主目的を大きく阻害する |
| 0 | 必要な要素が重なり・切れなどで読めず、主目的を果たせない |

この尺度も経路・ラベルの項目と影響が重なる。採点時は欠点にIDを付け、主たる減点項目を1つ指定する。同じ「中央通路不足」で配置・経路・ラベル・空間をすべて減点しない。別項目でも減点するなら、独立した別の観察事実を記す。欠点の根本原因と、読者に現れた症状は分けて記録する。

余白が無駄という判断には「その領域を縮めた候補で、可読性が落ちず、画面への収まりなどが改善した」という比較が望ましい。比較がない場合は改善候補に留める。初回01・02の面積や高さだけを根拠にした減点は再検討対象とし、元の得点は履歴として維持する。v0.2の正式採点は同じ基準で全10例を見直してから確定する。

## 次の比較実験

| 対象 | 一度に変える条件 | 維持する条件 | 確認する効果 |
| --- | --- | --- | --- |
| 05 | 初回配置の列間だけを広げる | ノード順序・方向・接続・ラベル | 通路幅だけでどこまで識別が改善するか |
| 05 | 左右配置を上下配置にする | 接続・文字サイズ・表示倍率 | 方向変更で混雑箇所が分散するか。面積変化も併記 |
| 06 | 入口だけを縦列にする | データ層とアプリ層の相対配置・接続 | 入口の向きが下層の通路に与える影響 |
| 10 | 書類追加だけを戻り先の側へ移す | 正常経路の軸・接続・ラベル内容 | ノード位置変更だけで交差と追い直しが減るか |
| 各修正版 | 問題のない通路を段階的に縮める | 構造・文字・読む倍率 | 識別が悪化し始める箇所と必要な余白 |

自動再配置で固定した条件まで変わった場合は、その比較を単独要因の実験として扱わない。固定には評価用overlayを使えるが、意味的なDSLには座標を埋め込まない。

各候補で、意味の保持、ノード・ラベルの重なり、接続先の識別、画面への収まりを確認する。さらにSVG寸法、交差・折れ数、線長を補助記録する。小さい図が勝つ、交差ゼロが勝つという判定にはしない。

追跡課題の例は05「管理APIが更新するDB」、06「QueueからWorkerまでの経路」、10「不足判定から再審査までの経路」。人が実施する場合は正答・迷った箇所・追跡時間を記録し、表示順を入れ替えて学習効果を抑える。時間を測っていない目視評価は実測として報告しない。

## 過去修正との照合による補足（2026-09-12）

[適用確認と根拠一覧](whitespace-retrospective.md)に、9月5日の修正記録と現在の回帰テストとの対応を記録した。関連する8ファイル・57件が成功。

手順3の通路予約の前に、独立した条件分岐の出口と接続先の入口を決める。幅の拡張だけでは同じ出口の曖昧さは解消できない。主経路が曖昧な場合は主軸を強制しない。明示順序・保存位置・ポート・ルーティング方針を守り、局所拡張後は周囲と祖先枠への影響を確認する。

余白配分と、意味的階層・文字組み・再計算の安定性は別の原則として扱う。過去修正との整合は確認できたが、一般化した最適化手法の有効性が証明されたわけではない。
